# 定义

**索引位置：** 事件消息文件和索引文件在Web服务器上的根目录（必须允许通过HTTP/HTTPS访问），例如：

```text
https://example.com/events/
```

**事件消息：** 由标题、图标、链接、描述、内容等信息构成的结构化JSON数据。

**事件消息ID：** 用于唯一标识事件消息的标识符，通常为自然数。

---

# URI

本协议支持使用URI链接表示特定的"索引位置"。

URI链接格式规范如下：

```text
协议方案名://用户名:密码@服务器地址:服务器端口/带层次的文件路径/?查询字符串#片段标识符
```

其中，协议方案名为 **eisp** 或 **eisps**：

- 基于HTTP使用 **eisp**
- 基于HTTPS使用 **eisps**

**URI规范遵循RFC 3986标准。**

### URI 示例

以下示例均表示位于 `http://example.com/events/` 的索引位置：

```text
# 基于HTTP
eisp://example.com/events/

# 基于HTTPS
eisps://example.com/events/

# 指定端口
eisp://example.com:80/events/
eisps://example.com:443/events/

# 携带身份验证信息
eisps://user:password@example.com/events/
eisps://user:password@example.com:443/events/

# 指定协议版本（使用查询字符串）
eisps://example.com/events/?version=30000-0
eisps://user:password@example.com/events/?version=30000-0

# 指定具体事件（使用片段标识符）
eisps://example.com/events/#1000
eisps://example.com/events/?version=30000-0#1000
eisps://user:password@example.com/events/?version=30000-0#1000
```

## 查询字符串

| 字段名 | 参数类型 | 参数规范 | 描述  | 示例  |
| --- | --- | --- | --- | --- |
| version | string | 版本代号-更新代号 | 指定目标服务所使用的EIS协议版本 | 30000-0 |

## 片段标识符

片段标识符用于在URI中直接标识特定事件。URI中的片段标识符字段将直接解析为事件ID。

# 安全

本协议用于单向信息发布（类似RSS），通常不存在明显的网络安全问题。

但在某些场景下需要确保发布信息的数据安全，本协议提供以下解决方案：

### HTTP基础认证

使用此方式无需修改索引位置上的文件，但需要配置Web服务器软件以实现认证。

客户端需要携带身份验证信息请求文件。当客户端未携带身份验证信息时，服务端应返回401状态码。

```text
eisps://user:password@example.com/events/
```

### 索引加密认证

使用此方式需要加密除 `index.json` 外的所有文件，并将加密相关元数据存储到 `index.json` 文件中。

如果服务端不支持HTTP基础认证，可以使用此方案确保信息安全。

> **注意：当前版本协议无法完全加密事件消息数据目录。攻击者仍可通过遍历方式列出索引位置上的事件消息（ID），并推测其发布时间。**

出于扩展性考虑，本协议不限制加密算法。您可以使用任何加密算法（包括非对称加密算法）加密数据。

被加密的JSON文件遵循以下格式：

```json
{
    "Type": "Encrypted",    // 文件类型标识（"Encrypted"表示已加密；未加密文件为null或"Normal"）
    "Data": "<BASE64...>",  // Base64编码的原文件数据
    "Tag": null,            // @NULLABLE 加密标签或备注信息
    "Extension": {}         // 扩展字段（根据使用场景自行增加）
}
```

加密元数据存储在 `index.json->Security->Encryption` 中。本协议不对加密算法做强制规定，这意味着：

- 您可以在元数据中包含解密密钥（相当于不加密）
- 您可以包含非对称加密的公钥、证书等
- 您也可以不包含任何密钥信息

# 规范

> 下列文件均存储在"索引位置"中。

## index.json

该文件存储事件索引服务的名称、简介、协议版本等信息。

以下为完整的标准示例：

```json
{
    "Information": {
        "Url": null,                    // @NULLABLE 服务器主页地址（为null表示未设置）
        "Icon": null,                   // @NULLABLE 服务器图标链接（为null表示未设置）
        "Title": "Event Index Server",  // 服务器名称
        "Description": [                // 服务器描述（多行文本数组，每个元素为一行）
            "Hello, World!"             // [示例] 描述文本
        ],
        "Maintainers": [                // 服务器维护者列表
            "Administrator"             // [示例] 维护者名称
        ],
        "Links": [                      // 服务器相关链接列表
            "https://example.com/"      // [示例] 链接地址
        ],
        "Emails": [                     // 服务器联系邮箱列表
            "administrator@example.com" // [示例] 邮箱地址
        ],
        "Extension": {}                 // 扩展字段（根据使用场景自行增加）
    },
    "Protocol": {
        "Version": {
            "Major": 3,                 // 主版本号（参与版本判断）
            "Minor": 0,                 // 次版本号（参与版本判断）
            "Patch": 0,                 // 修订版本号（参与版本判断）
            "Build": 0,                 // @NULLABLE 构建版本号（不参与版本判断，可为null）
            "Tag": null                 // @NULLABLE 版本标签（不参与版本判断，可为null，如"alpha"、"beta"等）
        },
        "Extension": {}                 // 扩展字段（根据使用场景自行增加）
    },
    "Security": {                       // @NULLABLE 安全相关选项（如无该字段表示不使用安全及加密选项）
        "Encryption": {                 // @NULLABLE 加密相关选项
            "Enabled": false,           // 是否启用加密（默认false）
            "Algorithm": null,          // @NULLABLE 加密算法名称（如"AES-256-GCM"、"RSA-4096"等）
            "Specification": null,      // @NULLABLE 密钥规格信息
            "Parameters": [],           // 密钥参数信息
            "Keys": {                   // 密钥字段（本协议不做详细规定，请根据使用场景自行决定）
                "Public": {             // @NULLABLE 公钥（可选）
                    "Format": null,     // @NULLABLE 密钥格式（如"PEM"、"DER"等）
                    "Data": null,       // @NULLABLE 密钥内容（Base64编码）
                    "Extension": {}
                },
                "Private": {            // @NULLABLE 私钥（可选）
                    "Format": null,     // @NULLABLE 密钥格式
                    "Data": null,       // @NULLABLE 密钥内容（Base64编码）
                    "Extension": {}
                },
                "Protected": {          // @NULLABLE 对称加密密钥（可选）
                    "Format": null,     // @NULLABLE 密钥格式
                    "Data": null,       // @NULLABLE 密钥内容（Base64编码）
                    "Extension": {}
                },
                "Chain": {              // @NULLABLE 证书链（可选）
                    "Format": null,     // @NULLABLE 证书格式（如"X.509"等）
                    "Data": null,       // @NULLABLE 证书内容（Base64编码）
                    "Extension": {}
                },
                "Extension": {}         // 扩展字段（根据使用场景自行增加）
            },
            "Extension": {}             // 扩展字段（根据使用场景自行增加）
        },
        "Extension": {}
    },
    "Extension": {}                     // 扩展字段（根据使用场景自行增加）
}
```

> **注意：`Security` 及 `Security.Encryption` 均为可选字段。为降低复杂性，建议仅在需要时添加。**

## counter.json

该文件存储最新事件消息的ID和对应的发布时间。

> 应用程序可在本地存储Counter文件的副本，以便判断服务器上是否存在新发布且未被获取的事件消息。

**客户端可通过轮询该文件快速判断服务器上是否存在新的事件消息，而无需轮询Index和Data文件。**

*此文件用于客户端轮询优化。*

以下为完整的标准示例：

```json
{
    "Status": true,         // 服务器是否存在事件消息（true表示存在，false表示没有事件消息）
    "Latest": 1000,         // 最新的事件消息ID
    "Time": 1300000000000,  // 13位Unix时间戳（毫秒），表示最新事件消息的发布时间
    "Extension": {}         // 扩展字段（根据使用场景自行增加）
}
```

## data.json

该文件存储每条事件消息的ID及其部分元数据。

> 客户端可通过读取该文件快速筛选"类型"、"标签"、"分类"，而无需逐个获取完整的事件消息文件。

以下为完整的标准示例：

```json
{
    "Index": [                          // JSON数组，所有事件消息应按特定顺序在此列出
        {
            "Id": 1000,                 // 事件消息ID（以下元数据应与事件消息文件中的值保持一致）
            "Hide": false,              // 是否隐藏（如为true，客户端应忽略该消息，无论标签分类是否匹配；默认为false）
            "Classes": {
                "Type": [               // 类型：用于区分消息类型（如"用户可读"、"程序可读"等），本协议不做规定；允许一条消息存在多个类型，可为空数组
                    "Normal"            // [示例] 类型标识
                ],
                "Categories": [         // 分类：用于详细区分消息，本协议不做规定；允许一条消息存在多个分类，可为空数组
                    "System"            // [示例] 分类标识
                ],
                "Tags": [               // 标签：用于详细标记消息，本协议不做规定；允许一条消息存在多个标签，可为空数组
                    "Test"              // [示例] 标签标识
                ]
            },
            "Time": 1300000000000,      // 事件消息发布时间（13位Unix时间戳，毫秒）
            "Extension": {}             // 扩展字段（根据使用场景自行增加）
        }
    ],
    "Extension": {}                     // 扩展字段（根据使用场景自行增加）
}
```

## data/<事件消息ID>.json

`data` 目录下的每个JSON文件表示一条事件消息，文件名由其ID构成，例如：

```text
data/1000.json
data/1001.json
data/1002.json
data/1003.json
data/1004.json
data/1005.json
...
```

以下为完整的标准示例：

```json
{
    "Id": 1000,                         // 事件消息ID
    "Hide": false,                      // 是否隐藏（如为true，客户端应忽略该消息，无论标签分类是否匹配；默认为false）
    "Classes": {
        "Type": [                       // 类型：用于区分消息类型，本协议不做规定；允许一条消息存在多个类型，可为空数组
            "Normal"                    // [示例] 类型标识
        ],
        "Categories": [                 // 分类：用于详细区分消息，本协议不做规定；允许一条消息存在多个分类，可为空数组
            "System"                    // [示例] 分类标识
        ],
        "Tags": [                       // 标签：用于详细标记消息，本协议不做规定；允许一条消息存在多个标签，可为空数组
            "Test"                      // [示例] 标签标识
        ]
    },
    "Time": 1300000000000,              // 事件消息发布时间（13位Unix时间戳，毫秒）
    "Data": {                           // 事件消息的具体数据
        "Title": "System Test",         // 事件消息标题（必填）
        "Icon": null,                   // @NULLABLE 事件消息图标URL（为null表示没有图标）
        "Type": "Text",                 // 事件消息内容类型（必填），表示正文内容的格式；可为任意类型，本协议不做详细规定，可根据使用场景自主区分（如"Text"、"Markdown"、"Html"等）
        "Uri": null,                    // @NULLABLE 事件消息的引用链接（为null表示没有引用链接）；可为任意格式/协议，本协议不做详细规定
        "Describe": "Hello, World!",    // 事件消息的描述或摘要（必填）
        "Content": [                    // 以换行符分割的事件消息正文数组（可为空）；按特定顺序排列，客户端读取时应在字符串之间添加换行符以合并为正文
            "Hello World, Hello World!" // [示例] 正文内容
        ]
    },
    "Files": [                          // @NULLABLE 事件消息附加的资源文件列表（如不添加资源文件，可省略此字段）
        {
            "Uri": "https://example.com/file.mp3", // @NULLABLE 资源文件URI地址（为null表示无资源文件）
            "Type": "audio/mpeg",       // @NULLABLE 资源MIME类型（为null表示未知类型，由客户端在需要时自行判断）
            "Length": -1,               // @NULLABLE 资源文件大小（字节）（值为-1或null表示未知大小，由客户端在需要时自行判断）
            "Extension": {}             // 扩展字段（根据使用场景自行增加）
        }
    ],
    "Extension": {}                     // 扩展字段（根据使用场景自行增加）
}
```
